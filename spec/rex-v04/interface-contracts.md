# Interface contracts

Status: every interface is `proposed`. None exists in code at the baseline commit unless its note says so.

[interfaces.kvx](interfaces.kvx) is the ledger. Each `[interface.<id>]` block carries the kind, the file that will own it, the signature workers code against, its single providing task, its consuming tasks and the contract in plain words.

## Rules

1. **One provider.** Exactly one task lists an interface in `provides`. That task creates it, tests it and documents it.
2. **Consumers wait.** A task that lists an interface in `consumes` starts only after the provider is done. Inside a wave it requires the provider, directly or through another task. Across waves its wave starts after the provider's wave has landed.
3. **The signature is the contract.** A consumer codes against the ledger signature. A provider that needs a different shape tells the wave manager before merging, and the manager updates the ledger and tells each consumer.
4. **Status moves forward.** `proposed` becomes `stable` when the providing task is done. A later change to a stable interface is a new task.
5. **No private side doors.** A consumer does not reach into the provider's module past the declared signature.
6. **Additive by default.** Existing public names keep working for one minor through a deprecated re-export, unless the task's clause says the old behaviour is itself the defect.

## Shared registries

Three files are touched by many tasks and are not interfaces in themselves: the error catalog in `packages/rex/src/core/errors.ts`, the configuration schema in `packages/rex/src/core/config.ts`, and the package entry `packages/rex/src/index.ts`. Workers append to them and never reorder or rewrite existing entries. The wave manager resolves merge order. The generated `docs/api` and `docs/errors.md` are regenerated by the manager at wave close, not by workers.

## Validation

`tools/validate_spec.py` fails when an interface has no provider or two, when a consumer list differs from the task declarations, when a same-wave consumer does not require its provider, or when a wave consumes from a wave it does not start after. See the generated table in [traceability.md](traceability.md).
