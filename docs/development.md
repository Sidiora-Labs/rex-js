# Developing Rex

This page is for people and agents working on Rex itself. For building apps with Rex, start at the [README](../README.md).

## Workspace layout

The repository is a pnpm workspace (`pnpm-workspace.yaml`: `packages/*` and `examples/*`). Node 22 or later is required (`engines` in `package.json`); pnpm is pinned to `10.27.0`.

```
packages/rex/            the @sidioralabs/rex package
  src/core/              primitives, protocol constants, stores, journal, flow
  src/manifest/          manifest types, builder, scanner, AGENTS.md renderer, sidecar schema
  src/server/            Hono server, oRPC action router, audit ledger, flow procedures, Node server
  src/client/            React runtime: app, router, nav, act, page host, shell, overlays
  src/client/agent/      addressing, sidecar, outcome region, palette, shortcuts, URL invocation, confirmation, density, flow gates
  src/check/             checker engine, source loader, formatters, rules/
  src/vite/              Vite plugin and virtual module generators
  src/cli/               CLI entry, templates, commands/
  src/store/             Drizzle store adapter
examples/demo/           the wallet demo app and its Playwright walk
spec/                    the Codify spec (kvx) and generated markdown mirrors
tools/                   release gates
```

`AGENTS.md` and `CLAUDE.md` at the root are generated from `spec/workflow.kvx` by `cg spec render`; do not edit them by hand. `examples/demo/AGENTS.md` is generated by `rex manifest`.

## Tests

### Unit and integration tests

`packages/rex/vitest.config.ts` defines two Vitest projects:

| Project | Environment | Files |
| --- | --- | --- |
| `node` | Node | `src/**/*.test.ts` |
| `dom` | happy-dom | `src/**/*.test.tsx` |

There are 42 test files next to the code they test. React tests use `@testing-library/react` and wouter's `memoryLocation`; server tests call real `createRexServer` apps; CLI tests run the CLI and generated apps for real. Shared test inputs:

- `src/check/fixtures/<rule>/{pass,fail}/` hold small apps that each rule must accept or reject; `src/check/fixtures/all` and `engine` serve the engine and `runCheck` tests.
- `src/client/fixtures/page-basic` and `page-second` are page folders used by the client tests.
- `src/manifest/fixtures` is the app used by the scanner tests.
- `src/core/store.conformance.ts` exports `runStoreConformance(name, makeStore)`, which the memory store and the Drizzle store tests both run.

Run one file with `pnpm -C packages/rex exec vitest run <path>`, the whole package with `pnpm -C packages/rex test`.

The code graph indexes these wouter locations from the tests as routes. They are test-only paths, not routes of any app:

| Route | Test |
| --- | --- |
| `* /` | `src/client/act.test.tsx`, `src/client/agent/flow.test.tsx`, `src/core/protocol.test.ts` (the initial memory location) |
| `* /nowhere` | `src/client/agent/address.test.tsx` (an unknown route renders not-found) |
| `* /board` | `src/client/agent/address.test.tsx` |
| `* /send` | `src/client/overlay.test.tsx` (overlay declaration drift) |
| `* /rex/echo` | `src/vite/vite.test.ts` (the dev server forwards `/rex` requests and the density header to the app server) |

Test helper functions and fixture types are indexed in [reference.md](reference.md).

### The operability walk

`examples/demo/e2e/operability.spec.ts` with the helpers in `examples/demo/e2e/walk.ts` and `examples/demo/playwright.config.ts` (Chromium, one worker, no retries, 240 second test timeout). The walk builds the demo, starts `dist/server.js` on a free port, and checks every page in `default` and `agent` density: one ready sidecar matching the manifest, the root density attribute, the addressed landmarks, sidecar parity with the visible controls, 44px hit targets in agent density, every action by click, key, URL and palette, and every overlay by Escape, by its close control and by typed input. A separate test runs as the `guest` actor and checks that disallowed actions are listed with a reason, disabled, and not executed. Reports are written to `examples/demo/e2e/report/<page>.json` (`PageReport`: page, actor, the checks per density, failures). The walk is a release gate, not a per-task check.

## Release gates

| Gate | Steps |
| --- | --- |
| `tools/gate-test.sh` | `pnpm install --frozen-lockfile`; `pnpm -C packages/rex test`; when `examples/demo/rex.config.ts` exists, `pnpm -C packages/rex build` and `pnpm -C examples/demo test` (rex check plus the Playwright walk) |
| `tools/gate-lint.sh` | `pnpm -r typecheck`; when `examples/demo/rex.config.ts` exists, `pnpm -C packages/rex build` and `pnpm -C examples/demo exec rex check`; then `cg spec render --check` |

`spec/workflow.kvx` names them as the hierarchy's `test_gate` and `lint_gate`. They run once per wave landing on the merged revision.

## The spec-driven workflow

Rex is built with Codify (`cg`) from a spec in `spec/`:

- `spec/workflow.kvx` is the operating contract: principles, the task loop, limits, the qualification log format, hard rules and the fleet hierarchy.
- `spec/rex/spec.kvx` is the feature spec: `[meta]`, `[decision]`, `[design]`, the acceptance criteria `[req.1]` to `[req.22]`, and the task list `[task.*]` with status, wave, requirements, touched files and one `verify_cmd` per task.
- `spec/rex/qualification.kvx` is the qualification log of findings that a task could not fix inside its own files.
- `spec/rex/requirements.md`, `design.md` and `tasks.md` are generated mirrors.

### The task loop

From `[loop]` in `spec/workflow.kvx`:

1. `cg brief`, then read the feature spec.
2. Claim the next eligible task: `cg spec claim-next --agent <name>`, or `cg spec next` then `cg spec start <id>`. A task is eligible when all its `requires` tasks are done and its `touches` do not conflict with a live claim.
3. Implement the whole task against its acceptance criteria and write the specified tests, without building or testing yet.
4. Qualify once: format touched files, one typecheck, one run of the task's `verify_cmd`; at most two repair cycles and 30 minutes.
5. Append an unrelated failure or contradiction to `spec/rex/qualification.kvx` (keys `task`, `file`, `symbol`, `observed`, `assumption`, `severity`; at most six lines).
6. `cg spec done <id>` (never `--force`) once `verify_cmd` passes.
7. Commit the task on its own.

The hard rules include: edit only the task's `touches`; never weaken a test or check to make it pass; no stubs or fakes; one gate per task; workspace suites and the browser walk run once per wave.

### Fleet hierarchy

`[hierarchy]` and `[role.*]` in `spec/workflow.kvx`:

| Role | Agent | Branch |
| --- | --- | --- |
| Main integrator | `rex-main` | `main` (the only writer to main) |
| Feature manager | `fm-rex` | `feature/rex`, based on `main` |
| Wave worker | `w-rex-<wave>` | `wave/rex/<wave>`, based on `feature/rex` |

Worktrees live under `.codegraph/worktrees`. Workers merge into the feature branch; the feature manager lands into main only through the main integrator. Pull requests and checkpoints are manual.

### Documentation closure

When every task is done, `@docs` closes the feature's documentation: `cg spec docs start`, `cg docs plan`, `cg docs packet` (evidence packet and claim ledger under `.codegraph/docs/<feature>/`), edit only the configured targets (`README.md`, `docs/**`, `CONTRIBUTING.md`, `CHANGELOG.md`), fill the claim ledger, `cg docs check`, commit, `cg docs close`.

## Commit message format

Every commit in this repository uses eight lines followed by a blank line and a trailer:

```
rex-main
fm-rex
2026-10-04
wave/rex/6
1e6c1a83bb062116c474ecee0d64fdc185019573
"Add the Playwright operability walk that builds and serves the demo and drives every action by click, key, URL and palette in both densities" [spec:rex/6.2]

Signed By Rex Wave Worker w-rex-6 | Powered by Claude Opus 5.5 and Codify©

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

| Line | Content |
| --- | --- |
| 1 | `rex-main` |
| 2 | `fm-rex` |
| 3 | the date |
| 4 | the branch the commit is made on |
| 5 | the 40-character SHA of `HEAD` before the commit |
| 6 | the title in double quotes, imperative and in sentence case, describing the real change, followed by the spec tag (`[spec:rex/<task>]`, `[spec:rex]` for landings, `[spec:rex/@docs]` for documentation) when there is one |
| 7 | blank |
| 8 | `Signed By <signer> \| Powered by <model> and Codify©`, where the signer is the role and agent, such as `Rex Wave Worker w-rex-6` or `Rex Feature Manager fm-rex` |

Then a blank line and `Co-Authored-By: <model> <noreply@anthropic.com>`. Write the message to a file and commit with `git commit -F <file>`.
