# Translate an app

Rex i18n is a flat message map per locale in `app/locales/<locale>.json`, a locale resolved per request, and labels and titles that may be message keys. There is no runtime i18n library: Rex formats messages with a small ICU-subset formatter on `Intl.PluralRules`.

## 1. Configure the locales

In `rex.config.ts`:

```ts
export default defineConfig({
  app,
  i18n: { locales: ["en", "fr"], default: "en", routing: "prefix" },
  server: (bundle) => createDemoServer(bundle),
});
```

- `locales` lists every supported locale; `default` is one of them.
- `routing: "prefix"` mounts every page under `/:locale` (`/fr/send`), and `nav.to` and `useNav().href` keep the prefix. `routing: "none"` (the default) keeps the routes as declared.

## 2. Write the messages

`rex new` writes `app/locales/en.json` with the app and home titles. Each file is a flat map of keys to messages:

```json
{
  "app.title": "Wallet",
  "portfolio.title": "Portfolio",
  "send.title": "Send",
  "send.label": "Send",
  "holdings.count": "{count, plural, one {# token} other {# tokens}} held",
  "send.summary": "Send {amount} {symbol} to {recipient}",
  "dust.state": "{hidden, select, true {Dust is hidden} other {Dust is shown}}"
}
```

`app/locales/fr.json` has the same keys. Messages support `{name}` placeholders, `{name, number}`, `{name, plural, ...}` with `#`, `=n` cases and `offset:`, `{name, selectordinal, ...}` and `{name, select, ...}`. A malformed message throws `MessageFormatError` with the position.

## 3. Use keys in declarations

A `label` or `title` that starts with `msg:` is a message key, resolved through the active locale everywhere it appears: the page heading, the document title, control labels, the palette, the outcome region and the sidecar.

```ts
export const send = action("send", {
  // ...
  label: "msg:send.label",
});

export default page("send", {
  route: "/send",
  chrome: { title: "msg:send.title", back: "portfolio" },
  // ...
});
```

`t(key, values)` from `@sidioralabs/rex/client` builds such a reference with values (`t("send.summary", { amount: "1", symbol: "ETH", recipient: "Alice" })` returns `msg:send.summary?amount=1&recipient=Alice&symbol=ETH`), for places that take a label string.

## 4. Translate component text

Regions read the active locale with hooks and pass plain strings to parts:

```tsx
import { region, useT } from "@sidioralabs/rex/client";
import { useWallet } from "../../hooks/useWallet.ts";
import BalanceHero from "./parts/BalanceHero.tsx";

export default region("hero", () => {
  const t = useT();
  const wallet = useWallet();
  if (wallet.data === undefined) return null;
  return (
    <BalanceHero
      name={wallet.data.account.name}
      held={t("holdings.count", { count: wallet.data.tokens.length })}
    />
  );
});
```

- `useT()` returns `t(key, values)` for the active locale.
- `useLocale()` returns `{ locale, locales, defaultLocale, routing, set }`; `set("fr")` switches the locale and stores it in the `rex-locale` cookie.

## How the locale is chosen

On the server, for every request, in this order: the URL prefix (with `routing: "prefix"`), the `rex-locale` cookie, the best match from `Accept-Language`, then `default`. Server rendering sets `<html lang>` and the translated title for that locale, and the client starts in the same locale.

## Checks

With `i18n` configured, `rex check` runs `i18n/literal`: a `label` or `title` in a declaration, or a `label`, `title` or `aria-label` attribute in a component, that is a plain string literal is reported with the hint to move it to `app/locales/<default>.json` and write `msg:<key>`. A `msg:` reference that is not a valid key is reported too. Texts that stay untranslated (a brand name) go under `check.i18n.allow` in `rex.config.ts`.

## Known gaps in 0.2.0

- The generated `rex:app` module does not yet import `app/locales/*.json` and call `registerI18n(registry, { config, messages })`, so messages reach the client and server rendering only when the app registers them itself.
- `defineConfig` accepts only `check.tokens` under `check`, so `check.i18n.allow` is read by the checker but rejected when `rex.config.ts` loads.
